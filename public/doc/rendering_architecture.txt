============================================================
PixiJS 数据驱动渲染引擎架构设计方案
============================================================

1. 核心理念
-----------
采用“逻辑与渲染完全解耦”的架构。游戏逻辑层只负责计算状态，渲染层只负责根据指令绘图。
通过一套自定义的 DSL (Domain Specific Language) 脚本实现录像保存、回放和视频导出。

2. 数据流向
-----------
实时游戏：逻辑模拟 -> 结构化数据 (内存) -> PixiJS 渲染器
录像保存：结构化数据 -> DSL 转换模块 -> .txt 脚本文件
录像回放：.txt 脚本文件 -> DSL 转换模块 -> 结构化数据 -> PixiJS 渲染器
视频导出：Remotion -> 读取 .txt 脚本 -> PixiJS 渲染器 -> MP4

3. 脚本规范 (DSL)
-----------------
采用平铺式指令流，易于人类阅读和流式解析。
示例：
[FRAME 0]
<SPRITE id="hero_1" src="hero_idle" x="500" y="300">  <!-- 这里的 hero_idle 可能是合图里的一个帧 -->
<SPRITE id="bg_1" src="forest_bg" x="0" y="0">        <!-- 这里的 forest_bg 可能是个独立大图 -->
<SPRITE 
    id="hero_01" 
    src="hero_idle"        
    x="520.5" y="300.0"         <!-- 坐标 -->
    anchorX="0.5"              <!-- 中心锚点 -->
    anchorY="0.5"              <!-- 中心锚点 -->
    scaleX="-1"               
    scaleY="-1"               
    rotation="0.1"
    alphaR="1.0"
    alphaG="0.5"
    alphaB="0.2"
    alpha="0.8"
    tint="#ffffff"            
    blendMode="normal"          
    zIndex="10"              <!-- 渲染层级 -->
    filter="outline(2)"     <!-- 描边滤镜 可以暂时不实现-->
>
<SPRITE id=hero src="hero.png" x=500 y=300>

// 渲染层建立的混合模式映射表
const blendModeMapping = {
    'none':     PIXI.BLEND_MODES.NONE,     // 关闭混合（全屏大背景、极致性能）
    'normal':   PIXI.BLEND_MODES.NORMAL,   // 正常 Alpha 混合（绝大多数普通精灵）
    'add':      PIXI.BLEND_MODES.ADD,      // 加法混合（特效、受击闪白、弹幕）
    'multiply': PIXI.BLEND_MODES.MULTIPLY, // 正片叠底（环境阴影、暗部）
    'subtract': PIXI.BLEND_MODES.SUBTRACT  // 减法混合（高级负片、数字故障特效）
};

[FRAME 1]
<BALL id=1 x=102.5 y=201.0>

* 关键点：每一帧记录的是“绝对位置”，支持随机跳帧访问，防止误差累积。

3.1 资源引用与命名契约 (Naming Convention)
- 独立图片：src="bg_forest.png" (不含 .@. 标记，作为独立 BaseTexture 处理)
- 合图子图：src="atlasID.@.子图id.png" (必须包含 .@. 标记)
    * 校验规则：同一个 ParticleContainer (group) 内的所有 PARTICLE 必须拥有相同的 atlasID。
    * 自动化：渲染器通过 .@. 标记自动识别并从对应的合图中提取纹理。

3.2 指令示例
[FRAME 0]
<SPRITE id=hero_01 src="hero.@.run" x=520.5 y=300.0 anchor=0.5>

<!-- 1. 定义粒子容器：显式绑定合图，可配置混合模式与全局特效 -->
<PARTICLECONTAINER id="fx_layer" atlas="fx_atlas" blendMode="add" tintAdd=#220000>
<!-- 2. 渲染普通精灵 -->
<SPRITE id="hero_01" src="hero.@.run" x=520.5 y=300.0 anchor=0.5>
<!-- 3. 渲染粒子：必须指定所属的 particleContainer -->
<PARTICLE id="p_103" particleContainer="fx_layer" src="fx.@.fire" x=100 y=200 scale=0.5 rotation=1.57 alpha=0.8>


4. 渲染层优化策略
-----------------
- 扁平化渲染：放弃复杂的 Container 嵌套，逻辑层直接计算绝对坐标。
- 对象池 (Object Pooling)：不重复创建/销毁精灵，根据 ID 复用已有的 Pixi 对象。
- 粒子容器 (ParticleContainer)：由逻辑层根据对象类型（如弹幕、粒子系统）显式指定容器归属，渲染层仅负责按指令挂载，实现 GPU 加速，避免渲染层进行实时启发式判断。
- 滤镜 (Filters)：作为可选属性附加在对象指令中，由渲染器统一处理。
- 颜色混合 (Tinting System)：
    * TintMultiply (默认)：<SPRITE tintMul=#FF0000>，实现原图与颜色的乘法混合（Pixi 原生支持）。
    * TintAdditive (提亮)：<SPRITE tintAdd=#550000>，实现原图与颜色的加法混合，常用于受击闪白。
    * TintSubtractive (变暗)：<SPRITE tintSub=#220000>，实现原图与颜色的减法混合。
    * 注意：渲染层通过 ColorMatrixFilter 统一实现 Additive 和 Subtractive 效果。
- 通道透明度 (Channel Alpha)：
    * alphaR / alphaG / alphaB：独立控制红、绿、蓝三个通道的强度。
    * 结合全局 alpha，可实现色差、分色淡出或高级数字故障特效。
    * 渲染层实现：通过 ColorMatrixFilter 的对角线元素进行实时映射。

5. 性能考量
-----------
- 优先使用 JSON 或结构化数据进行实时渲染。
- DSL 脚本仅用于持久化存储（录像）和跨平台交换。
- 追求“傻瓜式渲染器”原则：渲染器不带逻辑，只负责执行当前帧的数值赋值。

6. 后续扩展
-----------
- 二进制格式支持：若录像文件过大，可引入 TypedArrays (ArrayBuffer) 存储。
- 宏指令：支持自定义复杂图形的简写指令。

7. 音频管理策略 (Audio Management)
----------------------------------
- DSL 指令化：音频触发同样作为指令记录在 DSL 中。
  示例：<SOUND id=s1 src="boom.mp3" priority=10 vol=0.8>
- 浏览器适配：针对 Web Audio API 环境，采取极度保守的资源管理。
- 存在物理声道上限 (Physical Voice Limit)：强制限制在 8-12 个并发声道，防止浏览器内存溢出。
- 预解码对象池：常用音效预加载为 AudioBuffer，避免实时解码产生的 CPU 峰值。
- 音频节点池 (Audio Node Pooling)：
  * 预先创建固定数量的播放通道（SourceNode + GainNode 组合）。
  * 播放新声音时，直接复用闲置通道或抢占低优先级通道，仅替换 Buffer 数据。
  * 严禁在主循环中 new AudioContext 或频繁创建节点，将垃圾回收 (GC) 压力降至最低。
- 抢占式算法 (Preemption)：
  * 优先级排序：BGM(100) > 关键反馈(50) > 普通音效(10)。
  * 硬切断机制：当新高优先级声音进入时，立即 stop() 并重置最低优先级声道，不进行复杂的淡出计算以节省性能。
- 逻辑层过滤：
  * 距离过滤：超出视野范围的声音不进入 DSL。
  * 频率限制：同一 ID 的音效在极短时间内（如 50ms）不重复触发。
- Remotion 合成：导出时在 Node.js 环境下进行高质量多轨混音，不受浏览器声道限制。
