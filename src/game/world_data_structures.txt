# 游戏世界初始化数据结构定义 (ECS 规范)

本文档定义游戏引擎 ECS 架构的初始化 DSL 标签结构。DSL 采用 XML 格式。

## 1. 根容器 (World)

游戏世界的顶层容器。

<World>
    <EngineConfig>
        <SystemPipeline>
            <!-- 以下系统仅为示例，实际名称取决于你注册的系统 -->
            <System name="InputSystem" enabled="true" />
            <System name="AISystem" enabled="true" />
            <System name="PhysicsSystem" enabled="true" />
            <System name="ParticleSystem" enabled="true" />
            <System name="AnimationSystem" enabled="false" />
            <System name="RenderSystem" enabled="true" />
        </SystemPipeline>
    </EngineConfig>
    <Canvas name="battle_scene" width="1280" height="720" background="#020817" />
    <!-- GameObject -->
</World>

## 2. 引擎配置 (EngineConfig)

定义引擎的运行参数。

### 2.1 系统流水线 (SystemPipeline)

定义系统 (System) 的加载顺序和启用状态。系统将按照 XML 中定义的顺序执行。

<System 
    name="PhysicsSystem"            <!-- [必填] 系统名称 (需先在 GameEngine 中注册) -->
    enabled="true"                  <!-- [可选] 是否启用，默认 "true" -->
/>

粒子系统建议顺序：`PhysicsSystem -> ParticleSystem -> RenderSystem`。
其中 `ParticleSystem` 会将发射器生成的 `ParticleData[]` 批处理为 Pixi 粒子命令。

当工程启用输入-信号驱动时，建议顺序：
`InputSystem -> EventDispatchSystem -> Gameplay/AI/Physics -> RenderSystem`。

### 2.2 事件总线配置 (EventBus)

用于声明“允许发布/订阅的事件集合”以及 payload 结构约束。
推荐作为 `<EngineConfig>` 的直接子节点，作为项目级基线。

```xml
<EventBus
    mode="strict"
    unknownEvent="error"
    maxQueuePerFrame="2048"
>
    <EventCatalog>
        <Event id="core.scene.loaded" channel="lifecycle" sticky="true">
            <Payload>
                <Field name="sceneName" type="string" required="true" />
            </Payload>
        </Event>

        <Event id="combat.damage.applied" channel="combat">
            <Payload>
                <Field name="sourceId" type="entityId" required="true" />
                <Field name="targetId" type="entityId" required="true" />
                <Field name="amount" type="number" required="true" />
                <Field name="crit" type="boolean" required="false" default="false" />
            </Payload>
        </Event>
    </EventCatalog>
</EventBus>
```

字段说明：

- `mode`：`[可选]` 校验模式，支持 `strict` / `loose`，默认 `strict`。
  - `strict`：事件定义不合法即报错并中断加载（如 `Event.id` 重复、字段类型非法、payload 结构错误）。
  - `loose`：记录警告并跳过非法定义，其余合法事件继续注册；适合编辑期预览，不建议用于正式构建。
- `unknownEvent`：`[可选]` 未注册事件处理，支持 `error` / `warn` / `ignore`，默认 `error`。
- `maxQueuePerFrame`：`[可选]` 单帧事件队列上限，默认 `2048`。
- `Event.id`：`[必填]` 事件唯一标识。建议使用 `domain.subdomain.action`（如 `combat.damage.applied`）。
- `Event.channel`：`[可选]` 事件逻辑频道（用于调试/分流），默认 `default`。
  - 语义：用于给事件打“分类标签”，便于日志过滤、统计监控与中间件分流；不参与事件唯一性判定。
  - 适用：事件量较大或系统较多时，按 `combat|ui|input|network|lifecycle` 分组管理。
  - 不建议：把 `channel` 当作订阅主键；业务订阅应以 `Event.id` 为准。
- `Event.sticky`：`[可选]` 是否粘性事件（新订阅者可收到最后一次状态），默认 `false`。
  - 语义：事件总线会缓存该事件“最后一次 payload”；后续新订阅者在订阅瞬间会立即收到一次回放。
  - 适用：状态型事件（如 `core.scene.loaded`、`network.connected`）。
  - 不建议：瞬时动作事件（如 `input.jump.triggered`、`combat.damage.applied`），避免晚订阅导致误触发。
- `Field.name`：`[必填]` payload 字段名。
- `Field.type`：`[必填]` 字段类型，建议 `string|int|number|boolean|entityId|vector2|vector3`。
- `Field.required`：`[可选]` 是否必填，默认 `false`。
- `Field.default`：`[可选]` 缺省值；仅在 `required="false"` 时建议使用。

### 2.3 输入配置 (InputConfig)

定义输入设备策略、动作集合与底层绑定。输入系统只负责产出 Action 状态，不直接耦合业务逻辑。
职责边界：本节只定义“设备 -> Action”的映射，不定义业务事件触发时机。

```xml
<InputConfig mode="strict" devicePolicy="keyboard,mouse,gamepad" deadzone="0.15">
    <ActionMaps active="gameplay">
        <ActionMap id="gameplay" enabled="true">
            <Action id="move" type="axis2" />
            <Action id="jump" type="button" />
            <Action id="skill.primary" type="button" />
            <Action id="camera.zoom" type="axis1" />
        </ActionMap>

        <ActionMap id="ui" enabled="true">
            <Action id="ui.confirm" type="button" />
            <Action id="ui.cancel" type="button" />
            <Action id="ui.navigate" type="axis2" />
        </ActionMap>
    </ActionMaps>

    <Bindings>
        <Binding action="move" map="gameplay" kind="2dComposite">
            <Part name="up" path="Keyboard/W" />
            <Part name="down" path="Keyboard/S" />
            <Part name="left" path="Keyboard/A" />
            <Part name="right" path="Keyboard/D" />
        </Binding>
        <Binding action="move" map="gameplay" path="Gamepad/LeftStick" />

        <Binding action="jump" map="gameplay" path="Keyboard/Space" />
        <Binding action="jump" map="gameplay" path="Gamepad/South" />
        <Binding action="skill.primary" map="gameplay" path="Mouse/LeftButton" />
        <Binding action="camera.zoom" map="gameplay" path="Mouse/WheelY" processor="scale(0.1)" />

        <Binding action="ui.confirm" map="ui" path="Keyboard/Enter" />
        <Binding action="ui.cancel" map="ui" path="Keyboard/Escape" />
    </Bindings>
</InputConfig>
```

字段说明：

- `mode`：`[可选]` 输入配置校验模式，支持 `strict` / `loose`，默认 `strict`。
  - `strict`：配置不合法即报错并中断加载（如 action 不存在、ActionMap 不存在、2dComposite 缺 Part、枚举非法）。
  - `loose`：记录警告并跳过非法项，其他合法配置继续生效。
- `devicePolicy`：`[可选]` 允许设备集合，逗号分隔，默认 `keyboard,mouse`。
- `deadzone`：`[可选]` 全局死区，默认 `0.15`。
- `ActionMap.id`：`[必填]` 动作映射表 ID（如 `gameplay`、`ui`）。
- `ActionMap.enabled`：`[可选]` 是否启用该映射表，默认 `true`。
- `Action.id`：`[必填]` 动作 ID（语义化意图，不写业务实现）。
- `Action.type`：`[必填]` 动作类型，支持 `button|axis1|axis2`。
- `Binding.action`：`[必填]` 目标动作 ID。
- `Binding.map`：`[可选]` 目标动作表；为空时使用 `ActionMaps.active`。
- `Binding.path`：`[可选]` 单输入路径（如 `Keyboard/Space`、`Gamepad/LeftStick`）。
- `Binding.kind`：`[可选]` 绑定模式。`2dComposite` 表示由多个 Part 组成二维轴。
- `Binding.processor`：`[可选]` 输入后处理器表达式（如 `scale(0.1)`）。
- `Part.name`：`[必填]` 复合轴方向名，建议 `up/down/left/right`。
- `Part.path`：`[必填]` 方向输入路径。

### 2.4 输入到信号映射 (InputToSignalMap)

用于将 `Action` 的阶段变化统一映射为 `EventBus` 事件。推荐作为 `<EngineConfig>` 直接子节点。
职责边界：业务事件触发时机只在本节通过 `Route.phase` 定义，避免与 `InputConfig` 重复。

```xml
<InputToSignalMap defaultMap="gameplay">
    <Route action="move" phase="changed" emit="input.move.changed" throttleMs="16">
        <Payload>
            <Set key="axis" from="ctx.value" />
            <Set key="device" from="ctx.device" />
            <Set key="entityId" value="$player" />
        </Payload>
    </Route>

    <Route action="jump" phase="pressed" emit="input.jump.triggered">
        <Payload>
            <Set key="device" from="ctx.device" />
            <Set key="entityId" value="$player" />
        </Payload>
    </Route>

    <Route action="skill.primary" phase="pressed" emit="combat.skill.primary.requested" />
    <Route action="ui.confirm" map="ui" phase="pressed" emit="ui.confirm.requested" />
</InputToSignalMap>
```

字段说明：

- `defaultMap`：`[可选]` 默认动作表 ID（Route 未写 map 时使用）。
- `Route.action`：`[必填]` 来源动作 ID。
- `Route.map`：`[可选]` 来源动作表 ID。
- `Route.phase`：`[必填]` 动作阶段，支持 `pressed|released|held|changed`。
- `Route.emit`：`[必填]` 目标事件 ID（需在 EventBus 中注册，strict 下必须存在）。
- `Route.throttleMs`：`[可选]` 节流间隔（毫秒），常用于 `axis` / `changed` 类持续输入。
- `Set.key`：`[必填]` 输出 payload 键名。
- `Set.from`：`[可选]` 从输入上下文取值，常见 `ctx.action|ctx.value|ctx.device|ctx.path|ctx.time`。
- `Set.value`：`[可选]` 写入常量值（如 `$player`）。

## 3. 游戏对象 (GameObject)

代表 ECS 中的一个实体 (Entity)。它本身不包含逻辑，只作为组件的容器。

<GameObject 
    name="Player"                   <!-- [可选] 对象名称，用于调试 -->
    id="1001"                       <!-- [必填] 实体唯一标识 -->
>
    <!-- Components -->
</GameObject>

## 3. 组件 (Components)

挂载在 GameObject 下的数据结构。

### 3.1 变换组件 (Transform)

定义实体在空间中的位置、旋转和缩放。

<Transform 
    position="10, 20, 0"            <!-- [可选] x, y, z 坐标，默认 "0, 0, 0" -->
    parent="1001"                   <!-- [可选] 父实体 ID。填写后 position 解释为相对父 Transform 的局部坐标 -->
    rotation="45"                   <!-- [可选] 旋转角度（度），默认 "0"。解析器会自动转换为弧度 -->
    scale="1, 1, 1"                 <!-- [可选] x, y, z 缩放，默认 "1, 1, 1" -->
/>

父子关系示例（无需嵌套 XML）：

<GameObject name="Car" id="1001">
    <Transform position="100, 100, 0" />
    <RigidBody type="dynamic" />
</GameObject>

<GameObject name="Wheel" id="1002">
    <Transform position="20, -10, 0" parent="1001" />
    <Sprite texture="wheel.png" />
</GameObject>

### 3.2 精灵组件 (Sprite)

定义实体的视觉表现。

<Sprite 
    texture="player.png"            <!-- [必填] 纹理路径或 ID -->
    layer="1"                       <!-- [可选] 渲染层级，默认 "0" -->
    anchor="0.5, 0.5"               <!-- [可选] 锚点 x, y (0-1)，默认 "0.5, 0.5" -->
    alpha="1.0"                     <!-- [可选] 透明度 (0-1)，默认 "1.0" -->
    visible="true"                  <!-- [可选] 是否可见，默认 "true" -->
    tint="0xffffff"                 <!-- [可选] 颜色滤镜 (十六进制)，默认 "0xffffff" -->
/>

### 3.3 刚体组件 (RigidBody)

定义实体的物理属性。

<RigidBody 
    mass="50.0"                     <!-- [可选] 质量，默认 "1.0" -->
    type="dynamic"                  <!-- [可选] 类型：static, dynamic, kinematic，默认 "dynamic" -->
    linearVelocity="100, -200"      <!-- [可选] 初始线速度 x, y，默认 "0, 0" -->
    angularVelocity="0"             <!-- [可选] 初始角速度，默认 "0" -->
    restitution="1.0"               <!-- [可选] 弹性系数 (0-1)，默认 "0.2" -->
    friction="0.0"                  <!-- [可选] 摩擦系数，默认 "0.5" -->
    fixedRotation="false"           <!-- [可选] 是否固定旋转，默认 "false" -->
    bullet="false"                  <!-- [可选] 是否开启高速避障 (CCD)，默认 "false" -->
    gravityScale="1.0"              <!-- [可选] 重力缩放系数，默认 "1.0" -->
    density="1.0"                   <!-- [可选] 密度，默认 "1.0" -->
/>

### 3.4 盒碰撞体组件 (BoxCollider)

定义实体的矩形碰撞区域。

<BoxCollider 
    width="10"                      <!-- [必填] 宽度 -->
    height="20"                     <!-- [必填] 高度 -->
    offsetX="0"                     <!-- [可选] 相对偏移 X -->
    offsetY="0"                     <!-- [可选] 相对偏移 Y -->
/>

### 3.5 圆形碰撞体组件 (CircleCollider)

定义实体的圆形碰撞区域。

<CircleCollider 
    radius="10"                     <!-- [必填] 半径 -->
    offsetX="0"                     <!-- [可选] 相对偏移 X -->
    offsetY="0"                     <!-- [可选] 相对偏移 Y -->
/>

### 3.6 多边形碰撞体组件 (PolygonCollider)

定义实体的多边形碰撞区域。

<PolygonCollider 
    points="0,-10 10,10 -10,10"     <!-- [必填] 顶点列表，空格分隔坐标对，逗号分隔 x,y -->
/>

### 3.7 矢量图形组件 (Graphic)

定义实体的几何形状渲染。

<Graphic 
    kind="circleGraphic"            <!-- [必填] 形状种类：circleGraphic, rectangleGraphic, polygonGraphic 等 -->
    fillColor="#7ee7d9"             <!-- [可选] 填充颜色 -->
    fillAlpha="1.0"                 <!-- [可选] 填充透明度 -->
    strokeColor="#ffffff"           <!-- [可选] 描边颜色 -->
    strokeWidth="2"                 <!-- [可选] 描边宽度 -->
    radius="10"                     <!-- [kind=circleGraphic 时必填] 半径 -->
    width="20"                      <!-- [kind=rectangleGraphic 时必填] 宽度 -->
    height="20"                     <!-- [kind=rectangleGraphic 时必填] 高度 -->
    points="0,-10 10,10 -10,10"     <!-- [kind=polygonGraphic 时必填] 顶点列表 -->
/>

### 3.8 摄像机组件 (Camera)

定义场景的观察视角。通常挂载在一个专门的 GameObject 上。

<Camera 
    x="0"                           <!-- [可选] 摄像机 X 轴偏移，默认 "0" -->
    y="0"                           <!-- [可选] 摄像机 Y 轴偏移，默认 "0" -->
    z="0"                           <!-- [可选] 摄像机 Z 轴偏移 (推进/拉远)，默认 "0" -->
    focus="400"                     <!-- [可选] 焦点距离 (控制伪 3D 投影)，默认 "400" -->
/>

### 3.9 粒子发射器组件 (ParticleEmitter)

定义一个粒子发射器。系统每帧会把粒子数据写入 `ParticleData[]`，再批量同步到 Pixi 粒子容器。

<ParticleEmitter
    maxParticles="200"              <!-- [可选] 粒子上限，默认 "200" -->
    emissionRate="30"               <!-- [可选] 每秒发射数量，默认 "30" -->
    texture="spark.png"             <!-- [可选] 粒子纹理路径（推荐）。未提供时可配合 graphicKind 使用纯色点粒子 -->
    graphicKind="circleGraphic"     <!-- [可选] 简单图形模式：circleGraphic / squareGraphic -->
    lifetimeMin="0.5"               <!-- [可选] 最小生命周期（秒），默认 "0.5" -->
    lifetimeMax="1.5"               <!-- [可选] 最大生命周期（秒），默认 "1.5" -->
    speedMin="50"                   <!-- [可选] 最小速度，默认 "50" -->
    speedMax="120"                  <!-- [可选] 最大速度，默认 "120" -->
    angle="-90"                     <!-- [可选] 发射主方向（度），默认 "-90" -->
    spread="45"                     <!-- [可选] 扩散角（度），默认 "45" -->
    startColor="#ffaa00"            <!-- [可选] 起始颜色，默认 "#ffaa00" -->
    endColor="#ff0000"              <!-- [可选] 结束颜色，默认 "#ff0000" -->
    startSize="1.5"                 <!-- [可选] 起始缩放，默认 "1.5" -->
    endSize="0.2"                   <!-- [可选] 结束缩放，默认 "0.2" -->
    startAlpha="1.0"                <!-- [可选] 起始透明度，默认 "1.0" -->
    endAlpha="0.0"                  <!-- [可选] 结束透明度，默认 "0.0" -->
    blendMode="add"                 <!-- [可选] 混合模式，默认 "add" -->
    anchor="0.5, 0.5"               <!-- [可选] 粒子锚点，默认 "0.5,0.5" -->
/>

### 3.10 动画资产组件 (Animations)

定义实体可播放的 XML 动画资产（标签集合 / Clip 集合）。
该组件只描述动画数据本身，不包含运行时播放状态。

建议与 `AnimationController` 组件配合使用，并在 `SystemPipeline` 中启用 `AnimationSystem`。

```xml
<Animations defaultLabel="idle">
    <Label name="idle" duration="30" loop="true" speed="1.0">
        <Track prop="sprite.textureFrame" interpolation="hold">
            <Key frame="0" value="idle_01" />
            <Key frame="10" value="idle_02" />
        </Track>
        <Track prop="transform.position.y" interpolation="linear" valueMode="relative">
            <Key frame="0" value="0" />
            <Key frame="15" value="-6" easing="cubic-bezier(0.25, 0.10, 0.25, 1.00)" />
            <Key frame="30" value="0" />
        </Track>
    </Label>

    <Label name="attack" duration="18" loop="false">
        <Track prop="sprite.textureFrame" interpolation="hold">
            <Key frame="0" value="atk_01" />
            <Key frame="6" value="atk_02" />
            <Key frame="12" value="atk_03" />
        </Track>
    </Label>
</Animations>
```

字段说明：

- `defaultLabel`：`[可选]` 默认播放标签名。未提供时可由 `AnimationController.currentLabel` 决定。
- `Label.name`：`[必填]` 标签名（全组件内唯一）。
- `Label.duration`：`[必填]` 动画长度（帧）。
- `Label.loop`：`[可选]` 是否循环，默认 `"true"`。
- `Label.speed`：`[可选]` 标签内默认速率倍率，默认 `"1.0"`。
- `Track.prop`：`[必填]` 目标属性路径（建议使用组件语义路径，如 `transform.position.x`、`sprite.alpha`）。
- `Track.interpolation`：`[可选]` 插值方式，支持 `hold` / `linear`，默认 `hold`。
- `Track.valueMode`：`[可选]` 数值语义，支持 `absolute` / `relative`，默认 `absolute`。
- `Key.frame`：`[必填]` 关键帧号，需升序且在 `[0, duration]` 范围内。
- `Key.value`：`[必填]` 关键帧值（number/string/boolean，按 `prop` 类型解析）。
- `Key.easing`：`[可选]` 该关键帧到下一关键帧的缓动曲线。支持 `cubic-bezier(x1, y1, x2, y2)`，例如 `cubic-bezier(0.25, 0.10, 0.25, 1.00)`；不填写表示无曲线（按 `Track.interpolation` 直接插值/保持）。
- `Key.easing` 建议仅用于数值属性轨道，且通常配合 `Track.interpolation="linear"` 使用。

`Track.valueMode` 语义说明（用于区分绝对值/相对值）：

- `absolute`：`Key.value` 为目标属性的绝对值。例如 `transform.position.y=360`。
- `relative`：`Key.value` 为相对偏移量（delta），每帧结果 = `标签开始时的基准值 + 采样值`。
- `relative` 模式下不应做“逐帧累加”；否则会出现 y 持续漂移。
- 建议：位移动画（如 bob 上下浮动）使用 `relative`；明确落点动画使用 `absolute`。

### 3.11 动画控制组件 (AnimationController)

定义实体动画的运行时控制状态（当前标签、播放帧、倍速、暂停等）。
该组件不保存轨道资产，只消费 `Animations` 中的标签数据。

```xml
<AnimationController
    playing="true"
    currentLabel="idle"
    localFrame="0"
    speedScale="1.0"
    direction="forward"
    loopOverride=""
    fallbackLabel="idle"
    actions="setLabel,playOnce,pause,resume,setSpeed,setLoopOverride"
/>
```

字段说明：

- `playing`：`[可选]` 是否播放中，默认 `"true"`。
- `currentLabel`：`[可选]` 当前播放标签；未提供时回退到 `Animations.defaultLabel`。
- `localFrame`：`[可选]` 当前标签内帧游标，默认 `"0"`。
- `speedScale`：`[可选]` 全局播放速度倍率，默认 `"1.0"`。
- `direction`：`[可选]` 播放方向，`forward` / `backward`，默认 `forward`。
- `loopOverride`：`[可选]` 循环覆盖值（`true` / `false`）。为空时沿用标签 `loop` 配置。
- `fallbackLabel`：`[可选]` 用于 `playOnce` 动作的回退标签。非循环播放结束后会切回该标签。
- `actions`：`[可选]` 允许被 `SignalBindings` 调用的动作白名单，逗号分隔。
  不填写时默认允许：`setLabel,playOnce,pause,resume,setSpeed,setLoopOverride`。

支持动作（与当前实现对齐）：

- `setLabel`：切换到指定标签。常用参数：`label`、`restart`（可选）、`keepPlaying`（可选）。
- `playOnce`：从 0 帧播放一次并强制 `loopOverride=false`。常用参数：`label`、`fallbackLabel`（可选）。
- `pause`：暂停播放（`playing=false`）。
- `resume`：继续播放（`playing=true`）。
- `setSpeed`：设置 `speedScale`。常用参数：`speed`。
- `setLoopOverride`：设置循环覆盖。常用参数：`loop`（`true` / `false`；不传表示清空覆盖）。

组合示例：

```xml
<GameObject name="Hero" id="hero_01">
    <Transform position="640, 360, 0" />
    <Sprite texture="hero_idle_01.png" layer="2" anchor="0.5, 0.5" />

    <Animations defaultLabel="idle">
        <Label name="idle" duration="20" loop="true">
            <Track prop="sprite.alpha" interpolation="linear" valueMode="absolute">
                <Key frame="0" value="1.0" />
                <Key frame="10" value="0.85" easing="cubic-bezier(0.25, 0.10, 0.25, 1.00)" />
                <Key frame="20" value="1.0" />
            </Track>
        </Label>
    </Animations>

    <AnimationController
        currentLabel="idle"
        playing="true"
        fallbackLabel="idle"
        actions="setLabel,playOnce,pause,resume,setSpeed,setLoopOverride"
    />
</GameObject>
```

### 3.12 信号绑定组件 (SignalBindings)

定义实体如何消费事件并触发 Controller 动作。  
职责边界：本组件只描述“事件 -> 动作”的规则，不负责输入采样（`InputConfig`）和输入转事件（`InputToSignalMap`）。

```xml
<SignalBindings>
    <On event="input.move.changed" target="AnimationController" action="setLabel" priority="10">
        <When expr="payload.axis && (payload.axis.x !== 0 || payload.axis.y !== 0)" />
        <Args label="run" restart="false" />
    </On>

    <On event="input.move.changed" target="AnimationController" action="setLabel" priority="5">
        <When expr="payload.axis && payload.axis.x === 0 && payload.axis.y === 0" />
        <Args label="idle" />
    </On>

    <On event="input.jump.triggered" target="AnimationController" action="playOnce" priority="100">
        <Args label="jump" fallbackLabel="idle" />
    </On>
</SignalBindings>
```

字段说明：

- `On.event`：`[必填]` 监听的事件 ID（如 `input.jump.triggered`）。
- `On.target`：`[必填]` 目标组件名。当前实现仅支持 `AnimationController`。
- `On.action`：`[必填]` 目标组件动作名（需在目标组件 `actions` 白名单内）。
- `On.priority`：`[可选]` 规则优先级，数字越大越先执行，默认 `0`。
- `When.expr`：`[可选]` 触发条件表达式；返回 `true` 才执行动作。
- `Args`：`[可选]` 动作参数容器。其所有属性都会作为参数传入动作。

`When` / `Args` 上下文约定（当前实现）：

- `When.expr` 可读取 `payload` 与 `self`：
  - `payload`：事件载荷；
  - `self`：当前实体对象（可用 `self.id`）。
- `Args` 属性值支持 primitive 自动解析：
  - `"true"/"false"` -> boolean；
  - 数字字符串 -> number；
  - 其他 -> string。
- `Args` 中若写 `payload.xxx` 字符串，将按路径从 payload 读取值；
  例如：`<Args speed="payload.value" />`。
- `Args` 中若写 `self.id`，会映射为当前实体 ID。

执行顺序建议：

1) `InputSystem` 读取输入并更新 Action 状态；  
2) `InputToSignalMap` 按 `Route.phase` 产出事件；  
3) `SignalBindings` 消费事件并触发 Controller action；  
4) 各业务系统（如 `AnimationSystem`）在下一步根据 Controller 状态生效。

组合示例（输入 -> 事件 -> 动画动作）：

```xml
<GameObject name="Hero" id="hero_01">
    <Animations defaultLabel="idle">
        <Label name="idle" duration="20" loop="true">
            <Track prop="sprite.alpha" interpolation="linear" valueMode="absolute">
                <Key frame="0" value="1.0" />
                <Key frame="10" value="0.85" />
                <Key frame="20" value="1.0" />
            </Track>
        </Label>
        <Label name="jump" duration="14" loop="false">
            <Track prop="sprite.alpha" interpolation="hold" valueMode="absolute">
                <Key frame="0" value="1.0" />
                <Key frame="14" value="1.0" />
            </Track>
        </Label>
    </Animations>

    <AnimationController
        currentLabel="idle"
        playing="true"
        fallbackLabel="idle"
        actions="setLabel,playOnce"
    />

    <SignalBindings>
        <On event="input.jump.triggered" target="AnimationController" action="playOnce">
            <Args label="jump" fallbackLabel="idle" />
        </On>
    </SignalBindings>
</GameObject>
```

## 5. 预制体 (Prefab) [扩展格式]

用于复用常见实体结构（例如：弹跳球、敌人单位、静态墙体）。
该格式是对现有 DSL 的向后兼容扩展：不使用 Prefab 时，原有 GameObject 写法保持不变。

### 5.1 预制体库 (PrefabLibrary)

预制体定义容器，作为 <World> 的直接子节点。
支持两种写法：
1) 内联写法（在当前 XML 内写完整 GameObject）
2) 跨文件写法（仅写 public 下相对路径，解析器自动加载）

<PrefabLibrary>
    <!-- 内联写法 -->
    <Prefab id="bouncing_circle">
        <GameObject name="CircleTemplate">
            <!-- Components -->
        </GameObject>
    </Prefab>

    <!-- 跨文件写法：src 为 public 目录下的相对路径 -->
    <Prefab id="enemy_unit" src="prefabs/enemy_unit.xml" />
    <Prefab id="wall_base" src="public/prefabs/wall_base.xml" />
</PrefabLibrary>

<Prefab
    id="ally_unit"                  <!-- [可选] 不写时可使用外部文件中的 id -->
    src="prefabs/ally_unit.xml"     <!-- [可选] public 下相对路径 -->
    extends="unit_base"             <!-- [可选] 继承的父预制体 ID -->
>
    <!-- 内联模式下写 <GameObject>；使用 src 时可省略 -->
</Prefab>

### 5.2 外部预制体文件格式 (public/*)

当使用 src 跨文件引用时，外部文件允许以下根节点之一：

1) <Prefab> 根

public/prefabs/enemy_unit.xml
<Prefab id="enemy_unit">
    <GameObject name="EnemyTemplate">
        <!-- Components -->
    </GameObject>
</Prefab>

2) <GameObject> 根（最简文件）

public/prefabs/simple_wall.xml
<GameObject name="WallTemplate">
    <!-- Components -->
</GameObject>

3) <PrefabLibrary> 根

public/prefabs/group.xml
<PrefabLibrary>
    <Prefab id="first_prefab" export="true">
        <GameObject>
            <!-- Components -->
        </GameObject>
    </Prefab>
    <Prefab id="other_prefab">
        <GameObject>
            <!-- Components -->
        </GameObject>
    </Prefab>
</PrefabLibrary>

4) <World> 根（可用于复杂预览与测试）

public/prefabs/enemy_pack.xml
<World>
    <EngineConfig>...</EngineConfig>
    <Canvas ... />
    <PrefabLibrary>
        <Prefab id="enemy_main" export="true">
            <GameObject>
                <!-- Components -->
            </GameObject>
        </Prefab>
        <Prefab id="enemy_variant">
            <GameObject>
                <!-- Components -->
            </GameObject>
        </Prefab>
    </PrefabLibrary>

    <!-- 本文件内可写完整测试场景 -->
    <Instance prefab="enemy_main" id="preview_enemy_01" />
</World>

#### 5.2.1 跨文件导出选择规则

当 src 文件包含多个 Prefab（例如根为 <PrefabLibrary> 或 <World>）时，按以下顺序选择被引用目标：

1) 优先使用带 `export="true"` 的 Prefab（建议且应保持一个文件最多一个）。
2) 若一个都没标：
   - 可选策略 B（兼容）：若只有一个 Prefab，自动使用它；
   - 否则报错（避免歧义）。
3) 若 `export="true"` 超过一个，必须报错。

### 5.3 预制体实例 (Instance)

在场景中实例化预制体。Instance 作为 <World> 的直接子节点。

<Instance
    prefab="bouncing_circle"        <!-- [必填] 引用的预制体 ID -->
    id="obj-circle-01"              <!-- [必填] 实例实体 ID（全局唯一） -->
    name="BallA"                    <!-- [可选] 实例名称 -->
>
    <!-- [可选] 覆盖模板中的组件属性 -->
    <Transform position="200, 200, 0" />
    <RigidBody linearVelocity="200, 300" />
</Instance>

### 5.4 覆盖与合并规则

1) 合并顺序：模板组件 -> 实例覆盖组件，后者优先。
2) 组件键按 type 唯一：同一实体中每种组件类型最多一个。
3) 建议在模板中不写 GameObject.id，由 Instance.id 作为最终实体 ID。
4) 解析器需做深拷贝，避免多个实例共享同一数组/对象引用（如 Polygon points）。
5) 当 prefab 不存在、id 重复、组件格式非法时，解析应报错并中断加载。

### 5.5 推荐放置顺序

<World>
    <EngineConfig>...</EngineConfig>
    <Canvas ... />
    <PrefabLibrary>...</PrefabLibrary>
    <Instance ... />
    <GameObject ... />              <!-- 仍可与 Instance 混用 -->
</World>
