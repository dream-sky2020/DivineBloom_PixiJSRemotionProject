# 游戏世界初始化数据结构定义 (ECS 规范)

本文档定义游戏引擎 ECS 架构的初始化 DSL 标签结构。DSL 采用 XML 格式。

## 1. 根容器 (World)

游戏世界的顶层容器。

<World>
    <EngineConfig>
        <SystemPipeline>
            <!-- 以下系统仅为示例，实际名称取决于你注册的系统 -->
            <System name="InputSystem" enabled="true" />
            <System name="PhysicsSystem" enabled="true" />
            <System name="ParticleSystem" enabled="true" />
            <System name="BehaviorSystem" enabled="true" />
            <System name="RenderSystem" enabled="true" />
        </SystemPipeline>
    </EngineConfig>
    <Canvas name="battle_scene" width="1280" height="720" background="#020817" />
    <!-- GameObject -->
</World>

## 2. 引擎配置 (EngineConfig)

定义引擎的运行参数。

### 2.1 系统流水线 (SystemPipeline)

定义系统 (System) 的加载顺序和启用状态。系统将按照 XML 中定义的顺序执行。

<System 
    name="PhysicsSystem"            <!-- [必填] 系统名称 (需先在 GameEngine 中注册) -->
    enabled="true"                  <!-- [可选] 是否启用，默认 "true" -->
/>

粒子系统建议顺序：`PhysicsSystem -> ParticleSystem -> RenderSystem`。
其中 `ParticleSystem` 会将发射器生成的 `ParticleData[]` 批处理为 Pixi 粒子命令。

当工程启用行为系统时，建议顺序：
`InputSystem -> BehaviorSystem -> PhysicsSystem -> RenderSystem`。

### 2.2 输入配置 (InputConfig)

定义输入设备策略、动作集合与底层绑定。输入系统只负责产出 Action 状态，不直接耦合业务逻辑。
职责边界：本节只定义“设备 -> Action”的映射，不定义业务事件触发时机。

```xml
<InputConfig mode="strict" devicePolicy="keyboard,mouse,gamepad" deadzone="0.15">
    <ActionMaps active="gameplay">
        <ActionMap id="gameplay" enabled="true">
            <Action id="move" type="axis2" />
            <Action id="jump" type="button" />
            <Action id="skill.primary" type="button" />
            <Action id="camera.zoom" type="axis1" />
        </ActionMap>

        <ActionMap id="ui" enabled="true">
            <Action id="ui.confirm" type="button" />
            <Action id="ui.cancel" type="button" />
            <Action id="ui.navigate" type="axis2" />
        </ActionMap>
    </ActionMaps>

    <Bindings>
        <Binding action="move" map="gameplay" kind="2dComposite">
            <Part name="up" path="Keyboard/W" />
            <Part name="down" path="Keyboard/S" />
            <Part name="left" path="Keyboard/A" />
            <Part name="right" path="Keyboard/D" />
        </Binding>
        <Binding action="move" map="gameplay" path="Gamepad/LeftStick" />

        <Binding action="jump" map="gameplay" path="Keyboard/Space" />
        <Binding action="jump" map="gameplay" path="Gamepad/South" />
        <Binding action="skill.primary" map="gameplay" path="Mouse/LeftButton" />
        <Binding action="camera.zoom" map="gameplay" path="Mouse/WheelY" processor="scale(0.1)" />

        <Binding action="ui.confirm" map="ui" path="Keyboard/Enter" />
        <Binding action="ui.cancel" map="ui" path="Keyboard/Escape" />
    </Bindings>
</InputConfig>
```

### 2.3 输入到信号映射 (InputToSignalMap)

用于将 `Action` 的阶段变化统一映射为 `EventBus` 事件。推荐作为 `<EngineConfig>` 直接子节点。

```xml
<InputToSignalMap defaultMap="gameplay">
    <Route action="move" phase="changed" emit="input.move.changed" throttleMs="16">
        <Payload>
            <Set key="axis" from="ctx.value" />
            <Set key="device" from="ctx.device" />
            <Set key="entityId" value="$player" />
        </Payload>
    </Route>

    <Route action="jump" phase="pressed" emit="input.jump.triggered">
        <Payload>
            <Set key="device" from="ctx.device" />
            <Set key="entityId" value="$player" />
        </Payload>
    </Route>
</InputToSignalMap>

### 2.4 信号注册表 (SignalRegistry)

定义游戏中所有信号的数据契约（Payload 结构）。

```xml
<SignalRegistry>
    <!-- 定义全局信号：玩家得分改变 -->
    <Signal name="GLOBAL:SCORE_CHANGED">
        <Param name="playerId" type="string" />
        <Param name="newScore" type="number" />
        <Param name="delta" type="number" />
    </Signal>

    <!-- 定义本地信号：受到伤害 -->
    <Signal name="LOCAL:damaged">
        <Param name="amount" type="number" />
        <Param name="sourceId" type="string" />
    </Signal>
</SignalRegistry>
```
```

## 3. 游戏对象 (GameObject)

代表 ECS 中的一个实体 (Entity)。它本身不包含逻辑，只作为组件的容器。

<GameObject 
    name="Player"                   <!-- [可选] 对象名称，用于调试 -->
    id="1001"                       <!-- [必填] 实体唯一标识 -->
>
    <!-- Components -->
</GameObject>

## 4. 组件 (Components)

挂载在 GameObject 下的数据结构。

### 4.1 变换组件 (Transform)

定义实体在空间中的位置、旋转和缩放。

<Transform 
    position="10, 20, 0"            <!-- [可选] x, y, z 坐标，默认 "0, 0, 0" -->
    parent="1001"                   <!-- [可选] 父实体 ID。填写后 position 解释为相对父 Transform 的局部坐标 -->
    rotation="45"                   <!-- [可选] 旋转角度（度），默认 "0"。解析器会自动转换为弧度 -->
    scale="1, 1, 1"                 <!-- [可选] x, y, z 缩放，默认 "1, 1, 1" -->
/>

### 4.2 精灵组件 (Sprite)

定义实体的视觉表现。

<Sprite 
    texture="player.png"            <!-- [必填] 纹理路径或 ID -->
    layer="1"                       <!-- [可选] 渲染层级，默认 "0" -->
    anchor="0.5, 0.5"               <!-- [可选] 锚点 x, y (0-1)，默认 "0.5, 0.5" -->
    alpha="1.0"                     <!-- [可选] 透明度 (0-1)，默认 "1.0" -->
    visible="true"                  <!-- [可选] 是否可见，默认 "true" -->
    tint="0xffffff"                 <!-- [可选] 颜色滤镜 (十六进制)，默认 "0xffffff" -->
/>

### 4.3 刚体组件 (RigidBody)

定义实体的物理属性。

<RigidBody 
    mass="50.0"                     <!-- [可选] 质量，默认 "1.0" -->
    type="dynamic"                  <!-- [可选] 类型：static, dynamic, kinematic，默认 "dynamic" -->
    linearVelocity="100, -200"      <!-- [可选] 初始线速度 x, y，默认 "0, 0" -->
    angularVelocity="0"             <!-- [可选] 初始角速度，默认 "0" -->
    restitution="1.0"               <!-- [可选] 弹性系数 (0-1)，默认 "0.2" -->
    friction="0.0"                  <!-- [可选] 摩擦系数，默认 "0.5" -->
    fixedRotation="false"           <!-- [可选] 是否固定旋转，默认 "false" -->
    bullet="false"                  <!-- [可选] 是否开启高速避障 (CCD)，默认 "false" -->
    sensor="false"                  <!-- [可选] 是否作为传感器夹具，默认 "false" -->
    gravityScale="1.0"              <!-- [可选] 重力缩放系数，默认 "1.0" -->
    density="1.0"                   <!-- [可选] 密度，默认 "1.0" -->
/>

### 4.4 盒碰撞体组件 (BoxCollider)

定义实体的矩形碰撞区域。

### 4.10 行为组件 (Behavior) [核心逻辑入口]

用于挂载自定义代码逻辑。

```xml

    type="Boss"                     <!-- [必填] 注册在 GameObjectRegistry 中的类型名称 -->
    health="1000"                   <!-- [可选] 自定义属性，将作为 params 传入构造函数 -->
    difficulty="hard"
>
    <CustomData>extra info</CustomData> <!-- [可选] 子元素也会作为 params 传入 -->
</Behavior>
```

### 4.11 信号配置组件 (SignalConfig)

定义实体的“信号编排规则”。为了保持解耦，禁止直接跨实体触发 Action。支持将信号中的 Payload 映射到 Action 参数。

```xml
<SignalConfig>
    <!-- 监听本地信号：由本实体的组件（如 Timer, Behavior）发出 -->
    <On event="LOCAL:timer.done" target="GameObjectController" action="destroy" />

    <!-- 监听全局信号：支持参数映射 -->
    <!-- 将信号中的 newScore 映射为 Action 的 score 参数 -->
    <On event="GLOBAL:SCORE_CHANGED" target="Behavior:ScoreUI" action="updateDisplay">
        <Args score="fromPayload:newScore" />
    </On>
</SignalConfig>
```

- `event`: 格式为 `[SCOPE]:[SIGNAL_NAME]`。Scope 可选 `LOCAL` (默认) 或 `GLOBAL`。
- `target`: 格式为 `[TARGET_TYPE]`。**禁止使用 ENTITY 前缀跨实体操作**。
    - `GameObjectController`: 操作本实体的生命周期。
    - `Behavior:[BehaviorType]`: 触发本实体上特定类型的 Behavior 方法。
- `Args`: 传递给 Action 的参数。
    - 使用 `fromPayload:[Key]` 语法从信号数据中提取值。
    - 使用固定值（如 `speed="2.0"`）。

### 4.12 游戏对象控制组件 (GameObjectController)

用于管理实体生命周期。

```xml
<GameObjectController
    alive="true"
    destroyable="true"
    destroyDelayMs="0"
    actions="destroy"
/>

### 4.13 动画组件 (Animation)

#### 4.13.1 结构示例

```xml
<Animation defaultLabel="idle">
    <Label name="idle" duration="30" loop="true" speed="1.0">
        <Track prop="sprite.textureFrame" interpolation="hold">
            <Key frame="0" value="idle_01" />
            <Key frame="10" value="idle_02" />
        </Track>
        <Track prop="transform.position.y" interpolation="linear" valueMode="relative">
            <Key frame="0" value="0" />
            <Key frame="15" value="-6" easing="cubic-bezier(0.25, 0.10, 0.25, 1.00)" />
            <Key frame="30" value="0" />
        </Track>
    </Label>
</Animation>
```

#### 4.13.2 字段定义

- `defaultLabel`：`[可选]` 默认播放标签名。
- `activeLabel`：`[运行时]` 当前正在播放的标签名。
- `currentFrame`：`[运行时]` 当前播放到的帧数。
- `Label.name`：`[必填]` 标签名（组件内唯一）。
- `Label.duration`：`[必填]` 动画长度（帧），要求 `> 0`。
- `Label.loop`：`[可选]` 是否循环，默认 `true`。
- `Label.speed`：`[可选]` 标签内默认速率倍率，默认 `1.0`。
- `Track.prop`：`[必填]` 目标属性路径。
- `Track.interpolation`：`[可选]` `hold | linear`，默认 `hold`。
- `Track.valueMode`：`[可选]` `absolute | relative`，默认 `absolute`。
- `Key.frame`：`[必填]`，`0 <= frame <= duration`，同轨道严格升序且不可重复。
- `Key.value`：`[必填]`，`number | string | boolean`。
- `Key.easing`：`[可选]`，建议 `cubic-bezier(x1,y1,x2,y2)`。

#### 4.13.3 语义约束

- `relative` 模式是“基准值 + 采样值”，禁止逐帧累加。
- `interpolation=linear` 且 value 非 number 时，按离散切换处理。

## 7. 信号与通信系统 (Signals & Communication)

本节详细说明不同 Prefab 之间如何通过信号和 Behavior 构建复杂的交互系统。

### 7.1 信号作用域 (Signal Scopes)

1.  **LOCAL (本地)**: 仅在当前实体内部流转。用于组件间的微观协作（如：Timer 结束后销毁自己）。
2.  **GLOBAL (全局)**: 在整个游戏世界（World）中广播。用于 Prefab 间的宏观协作（如：Boss 死亡后打开关卡大门）。

### 7.2 发送信号 (Emitting)

#### A. 通过组件配置发送
许多内置组件支持在特定时机发送信号：
```xml
<Timer onCompleteSignal="GLOBAL:LEVEL_WIN" />
<CircleCollider onCollideSignal="LOCAL:hit" />
```

#### B. 通过 Behavior 代码发送
Behavior 实例可以通过内置方法向不同作用域发送信号：
```typescript
// 在 Behavior 逻辑中
this.emit("LOCAL:state_changed", { newState: "angry" }); // 本地
this.emit("GLOBAL:ACHIEVEMENT_UNLOCKED", { id: "first_blood" }); // 全局
```

### 7.3 接收信号与处理 (Handling)

信号的处理统一由 `SignalConfig` 组件编排。它扮演了“接线员”的角色，将信号路由到具体的逻辑处理函数（Action）。

#### 接收流程：
1.  **监听**: `SignalSystem` 捕获到信号及其 Payload。
2.  **匹配**: 查找所有挂载了 `SignalConfig` 且订阅了该信号的实体。
3.  **过滤 (When)**: 如果定义了 `when` 表达式，则进行条件判断。
4.  **映射 (Mapping)**: 根据 `Args` 配置，从 Payload 中提取数据。
5.  **执行 (Action)**: 调用目标组件的方法并传入映射后的参数。

### 7.4 Behavior 通信最佳实践

为了保持 Prefab 的独立性，建议遵循以下通信原则：

1.  **解耦发送**: Prefab A 内部发生重要事件时，只管 `emit("GLOBAL:EVENT_NAME")`，不需要知道谁在听。
2.  **配置接收**: Prefab B 是否响应 Prefab A 的事件，通过在 Prefab B 的 XML 中配置 `SignalConfig` 来决定。
3.  **接口化**: 在 Prefab 的 `Behavior` 中定义清晰的 `public` 方法作为 Action 入口。

**示例：解耦的“开关与灯”系统**

```xml
<!-- Prefab: 压力开关 -->
<Prefab id="pressure_plate">
    <GameObject name="Plate">
        <CircleCollider sensor="true" onCollideSignal="GLOBAL:PLATE_ACTIVATED" />
    </GameObject>
</Prefab>

<!-- Prefab: 自动门 -->
<Prefab id="auto_door">
    <GameObject name="Door">
        <Behavior type="DoorLogic" />
        <SignalConfig>
            <!-- 门自己决定监听哪个全局信号来开门 -->
            <On event="GLOBAL:PLATE_ACTIVATED" target="Behavior:DoorLogic" action="open" />
        </SignalConfig>
    </GameObject>
</Prefab>
```
